Turn AdGuard and uBlock Origin parameter-removal lists into one CLN 1.0 rule file you can load into Linkumori as a remote or custom rule file.

It reads lists such as Dandelion Sprout’s Actually Legitimate URL Shortener Tool and the AdGuard URL Tracking filter, converts every $removeparam rule, and lists what it couldn’t convert and why. Everything runs in your browser. Fetch asks the list’s address for the file directly from your browser; nothing is sent to this site.

Source lists

Add one or more lists. Several lists merge into one rule file: identical rules are kept once, and every list’s @@ exceptions apply to all of them, as when an ad blocker loads the lists together.

List addresses you enter are remembered in this browser only.

Options

Per site: ||amazon.*^, ||youtube.com^… so Linkumori only checks a site’s rules on that site. Rules that apply everywhere stay in clean-global.
Keys become clean-amazon.*, clean-global. A prefix keeps them apart from the built-in providers, which would otherwise share rule toggles.

Try a URL

Runs the converted rules on a URL the way Linkumori runs providers: the first matching provider that changes the URL wins, then the next pass starts on the new URL. It models a top-level page load (GET, first-party), so it’s an approximation; the custom rules editor in Linkumori simulates with the engine itself.

How rules are split into providers

RuleWhere it goes
||www.amazon.co.uk/dp^$removeparam=xProvider ||amazon.*^ when the list also names amazon.*, else ||amazon.co.uk^. The rule keeps its own pattern, so it still only fires there.
||amazon.$removeparam=thProvider ||amazon.*^, rule $removeparam=th.
$removeparam=si,domain=youtu.be|soundcloud.comOne copy in ||youtu.be^ and one in ||soundcloud.com^, with domain= dropped where the provider already says it. Unrelated ~ exclusions are dropped.
$removeparam=gclid · */?r=dir$removeparam · domain=~a.comThe global provider ("domainPatterns": ["*"]): they apply on every site.
@@…$removeparam=…Copied into every provider holding a filter it could guard, because on a page load Linkumori only checks a provider’s own @@ entries.
@@/unsub/?$removeparamOne regex in defaults.exceptions, which every rule of the file skips.

Merging. Rules from all lists go through the same split. A rule both lists contain is kept once (the report lists it under Duplicates), and a list’s @@ exceptions also guard the other lists’ rules on the same pages.

In Linkumori a filter’s domain= is checked against the URL being cleaned (for @@ entries, also against the page), so splitting domain= lists into site providers keeps the same behaviour, and for doc rules it matches AdGuard exactly. See the filter syntax reference for every modifier.
