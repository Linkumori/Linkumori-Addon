Core protection

Quietly cleans everything you load

Every protection ClearURLs users rely on, rebuilt for Firefox's Manifest V3.

Removes tracking parameters

utm_*, fbclid, gclid and hundreds more are stripped in the background, from the query and the fragment.

Skips redirect middlemen

Click-through links go straight to their destination, so tracking services never see the hop.

Stops search result rewriting

Google and Yandex can't swap result links for tracked versions when you click them.

Blocks hyperlink auditing

Link ping beacons that report your clicks are blocked.

Prevents ETag tracking

Cache validators can't be turned into a persistent identifier.

Guards the History API

Pages can't sneak tracking back into the address bar with pushState or replaceState.

Copy clean links

A context-menu entry copies any link already cleaned, ready to share.

Bulk cleaning tool

Paste a list of URLs and clean them all at once, without visiting any of them.

Optional domain blocking

Complete providers can block known tracking and ad domains outright, with a page that still lets you continue.

Beyond ClearURLs

The controls people asked for, shipped

ClearURLs users have requested a whitelist since 2020. Linkumori has one, and a lot more.

Per-site whitelist

Leave a site alone in one click from the popup. Patterns like *.example.com and example.* work, and everything a whitelisted page loads is covered.

Pause and tab whitelist

Pause cleaning for a while, until restart, or for one site in one tab until it closes.

Custom rules that win

Write your own providers in the built-in editor. They apply on top of built-in and remote rules, with a test lab to check them first.

Switch any rule off

Disable a single rule, a provider or a whole rule set without writing counter-rules. Restore it any time; toggles survive rule updates.

Multiple remote rule sources

Load several rule lists from endpoints you control, cached and refreshed on a schedule. Remote Rules Health shows errors, notices and each file's capabilities.

Overload mode

Merge built-in and remote rules provider by provider, then apply your custom rules on top, instead of picking one source.

CNAME uncloaking

Trackers hiding behind a first-party subdomain are resolved through DNS and matched against the real host.

Rule defaults you control

Set request types, exceptions and preprocessors for whole files, choose whose defaults win, and merge defaults across sources.

Live log and audit

See every cleaned request as it happens, inspect the merged rule set, and file a pre-filled report when a page breaks.

Themes and accessibility

Light, dark, midnight, sunset, ice-cold and legacy themes, plus accessibility options on every page, checked against WCAG 2.2 AA.

Translatable

Every string lives in _locales, so adding a language is one file and a pull request.

An open rule standard

Rules are written in CLN 1.0, a documented JSON format with a defined run order, lint checks and conformance vectors.

CLN Format 1.0

One rule format, with one exact run order

CLN (Clean Link Notation) is the JSON format for built-in, remote and custom rules. Version 1.0 (final) pins down run order, duplicate handling, toggle ids, escaping, redirect safety and remote file capabilities.

  1. exceptionsSkip the provider if one matches
  2. redirections · fieldRedirectionsOnly to absolute http(s) targets
  3. completeProviderBlock the request outright
  4. rawRulesRegexes against the whole URL, always first
  5. rules · referralMarketingParameters, sorted by order inside the stage
  6. $removeparam filtersLast, guarded by @@ exceptions
Read the standard Filter syntax reference 
{
  "cln": "1.0",
  "providers": {
    "amazon": {
      "domainPatterns": ["||amazon.*^"],
      "rawRules": ["\\/ref=[^/?]*"],
      "rules": [
        "qid",
        "$removeparam=/^pd_rd_[a-z]*$/i",
        {
          "id": "token-rewrite",
          "matchPattern": "token",
          "replacePattern": "clean-§1§",
          "order": 5
        }
      ],
      "referralMarketing": ["tag"],
      "exceptions": [
        "||amazon.com^/gp/redirector.html"
      ]
    }
  }
}
Privacy

Linkumori collects nothing

No telemetry, no analytics, no usage data. Every URL is cleaned locally in the extension.

Local by default. Built-in rules ship with each release. Nothing is fetched unless you turn on remote rules.

Remote rules are for people who run their own server. Whoever controls the endpoint can see your IP address and when you connect. Point Linkumori at infrastructure you control, or a local network address.

Remote files can't redirect or block on their own. Under CLN 1.0, a remote file's redirect and block entries wait for your acceptance.

This website makes no third-party requests either: no fonts, trackers or CDNs. Full privacy policy
