Open, filter, check and edit a Linkumori CLN 1.0 rule file in JSON or YAML, then download it.

It's for working on the bundled rules or your own custom rules. The same editor is in the main repository at tools/rules-editor/, where it can load the YAML source directly. You can find every provider for a site, a rule id or a pattern, edit just those providers and write them back into the full file. The editor checks syntax and the CLN structure as you type and converts between JSON and YAML. Press Ctrl/⌘-F to find text in the file. Everything runs in your browser and nothing is uploaded. Your last draft is kept in this browser only.

Editor

Load the bundled rules, open a file, or paste one in.

    Filtering

    Type in the filter box to list the providers that match. Plain text matches anywhere and ignores case. Tick Regex to use a regular expression. Search in limits the match to one part of each provider:

    Search inMatches
    Anywhereprovider name, patterns, rule ids and entries
    Provider namethe key under providers, such as linkumori-reddit.com
    Domain / URL patterndomainPatterns, urlPattern and indexPattern
    Rule ideach rule object's id and aliases
    matchPattern / entrystring entries and each rule object's matchPattern

    The Providers list beside the editor shows every provider in the file, with its domain pattern and how many entries it has. Typing in the filter box narrows the list. Click a name to jump to that provider, or use the pencil to edit that provider on its own. Arrow keys move through the list.

    The Filtered tab shows a smaller file with only the matching providers. You can edit it there. Apply to full file writes each provider back in place, adds any you created and removes any you deleted. The rest of the file stays as it was.

    Only matching rules keeps just the matching entries inside each provider. It's useful for reading. You can't apply a trimmed view back, because that would delete the rules it hides.

    What it checks

    • JSON or YAML syntax, with the line of each error.
    • A providers object and a cln value of "1.0" if one is set.
    • Unknown keys and wrong types on providers and rule objects, as listed in the filter syntax reference.
    • Providers with both domainPatterns and urlPattern, or with neither.
    • Rule objects with no matchPattern, and the same rule id used twice in one provider.
    • Regexes that don't compile: urlPattern, rawRules and /…/ values.

    These checks are a quick first pass. Run lint-rules from the CLI for the full validation Linkumori uses.
