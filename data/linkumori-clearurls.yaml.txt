Writing CLN Format 1.0 in YAML:
This file uses YAML to express the same CLN 1.0 data model. It is not the
ClearURLs Rules YAML format. Use the CLN field names and values shown below;
the CLI converts this source to JSON for the extension.

```yaml
cln: "1.0"
metadata:
  name: "Example Linkumori rules"
  version: "1.0.0"
  description: "Example rules for a shop"
defaults:
  active: true
  description: "Default rule description"
  requestTypes:
    - main_frame
    - xmlhttprequest
  preprocessors:
    - type: urlDecode
      inputs: all
  exceptions:
    - '^https://shop\.example/keep'
  historyBypassProtection: true
providers:
  shop:
    # Use domainPatterns or urlPattern. Do not use both.
    domainPatterns:
      - "||shop.example^"
    rules:
      - "utm_source"
      - id: "token-rewrite"
        matchPattern: "token"
        replacePattern: "clean-§1§"
        order: 10
        requestTypes:
          - main_frame
        active: true
        description: "Rewrite the token parameter value"
    rawRules:
      - '\/ref=[^/?#]*'
    referralMarketing:
      - "tag"
    exceptions:
      - "||accounts.shop.example^"
    redirections:
      - "||go.shop.example^$redirect=https://shop.example/"
    fieldRedirections:
      - "redirect"
    completeProvider: false
    forceRedirection: false
    methods:
      - GET
    resourceTypes:
      - main_frame
      - xmlhttprequest
    historyBypassProtection: true
    active: true
```

Top-level keys are `cln`, `metadata`, `defaults`, and `providers`. For each
provider, the supported keys are `domainPatterns`, `urlPattern`, `indexPattern`,
`rules`, `rawRules`, `referralMarketing`, `exceptions`, `redirections`,
`fieldRedirections`, `completeProvider`, `forceRedirection`, `methods`,
`resourceTypes`, `historyBypassProtection`, and `active`. A rule can be a string
or an object; rule-object fields include `id`, `aliases`, `matchPattern`,
`replacePattern`, `preprocessors`, `requestTypes`, `exceptions`, `order`,
`referralMarketing`, `active`, `flags`, `historyBypassProtection`,
`description`, and `targetId` where applicable. The optional top-level `patches`
key is for remote rule files only.

Remote-file patch example:

```yaml
cln: "1.0"
patches:
  - target: "shop::token-rewrite"
    section: rules
    replace:
      matchPattern: "token"
      replacePattern: "safe-§1§"
      order: 20
    description: "Use a different token rewrite"
```

Quote rule strings, regular expressions, URLs, and parameter names that could
be parsed as numbers or YAML keywords. Keep booleans and numeric fields such as
`active`, `completeProvider`, `forceRedirection`, and `order` as YAML booleans
and numbers. Read docs/filter-syntax.md for the full field definitions, value
syntax, supported patterns, rule ordering, and remote-patch format.
